### 测试基建踩坑记录（后续写测试直接抄，别再踩）

1. **GoRouter**：页面里会 `context.go()`，测试树里必须真的挂 GoRouter 控件。
   - `MaterialApp.router` **没有** `home` 参数；flutter 的 `Router` **不接受** `child`；
     直接 `Router(routerConfig:)` 会编译不过。
   - 唯一可行姿势：**`GoRouter` 自带 `/smoke` 路由 + `MaterialApp.router(routerConfig: router)`**，
     页面作为该路由的 `builder` 内容。否则 `No GoRouter found in context`。
2. **`pumpAndSettle` 会超时**：`AppSettingsPage` / `EditLibraryPage` 开局拉数据转圈，
   永远等不到静止。改用**有界 pump 循环**（`15 × 50ms`）代替。
3. **私有开关组件**：`_MusicFlowToggle` 是 `AnimatedContainer`（外层 52×30 底槽 +
   内层 `AnimatedAlign` 滑块），`find.byType(AnimatedContainer)` 会匹配到 3 个，
   必须按 `(w is AnimatedContainer && w is! AnimatedAlign && w.decoration is BoxDecoration)` 挑。
4. **ListView 骨架**：`MusicFlowProviderListSkeleton` 是 `ConsumerStatefulWidget`，
   外层必须套 `ProviderScope`（否则 `Bad state: No ProviderScope found`），
   且要给它有限高度（默认无界会 layout 报错）。
5. **SharedPreferences 桩**：`SharedPreferences.setMockInitialValues({...})` 后取 `getPrefs()`。
6. **L10n**：`AppLocalizations` 是 abstract，不能 `const AppLocalizations()`；
   取当前 locale 用 `lookupAppLocalizations(const Locale('zh'))`。

## 三、发现的真实缺陷清单（待统一修复）

> 缺陷在测试里用 `// [D-xxx]` 标注，当前测试**断言的是「现状」**，
> 修复源码后需把对应用例的断言翻转（标注处有说明）。
> 优先级：P0 = 会导致用户可见错误行为；P1 = 语义/健壮性问题；P2 = 打磨项。

| ID | 位置 | 触发条件 | 当前行为 | 严重度 | 修复建议 |
|----|------|---------|---------|--------|---------|
| **D-001** | `lib/data/models/server_config.dart:30-31` `ServerConfig.fromJson` | JSON 里缺 `serverUrl` / `username` | `json['serverUrl'] as String` 是**硬 cast**，直接抛 `TypeError` 崩溃，而不是回落空串 | P1 | 改为 `json['serverUrl'] as String? ?? ''`（配合既有的空串校验），避免解析层崩溃 |
| **D-002** | `lib/data/models/offline_cache_size.dart:69-71` `fromBytesFloor` | `bytes <= 0`（脏配置 / 计算溢出） | 返回 **`g2`（2GB）默认档**，而不是最小档 `g1`。与「floor（向下取档）」的命名语义相悖，用户会看到自己没设过的 2GB | P2 | `bytes <= 0` 时返回 `OfflineCacheSize.g1`（最小档），或显式命名 `fromBytesFloor(0, fallback: g2)` |
| **D-003** | `lib/core/utils/lrc_parser.dart` `LrcParser.parse` | 歌词里**混排**了无时间戳的文本行 | 无时间戳行 `startMs == null`，排序时用 `?? 0` 会被**顶到最前面**显示 | P1 | 无时间戳行追加到结果**末尾**（`startMs = Duration.zero` 排序时用「最后」占位，或单独挂到尾部集合） |
| **D-004** | `lib/core/utils/lrc_parser.dart:7` `_timeTagRegExp = \[(\d{1,3}):(\d{2})\.(\d{2,3})\]` | 一位毫秒，如 `[00:01.5]` | 正则只吃 2~3 位小数，**识别不了 1 位**；整行被判为无时间戳文本，歌词显示成残标 | P1 | 正则改成 `\[(\d{1,3}):(\d{2})\.(\d{1,3})\]`（并把捕获组当小数处理，`ms = int * 10^(3-len)`） |
| **D-005** | `lib/data/models/search.dart:234-242` `SearchArtist.fromLocal` | 本地艺人转搜索结果 | 只填 `id/name/avatar/albumCount`，**`songCount` 恒为空串**——`SearchArtist` 模型明明有该字段 | P2 | `songCount: artist.songCount?.toString() ?? ''` |
| **D-006** | `lib/data/models/artist.dart:31`、`album.dart:54`、`song.dart:229` | 服务端**显式**下发 `"starred": false` | 用的是 `json['starred'] != null` → `false` 被判成 **已收藏**。只有 `song.dart` 用了正确的 `switch` 显式分支，`artist/album` 没跟上 | **P0** | 三处统一成 `song.dart` 的写法：`switch (json['starred']) { bool v => v, _ => json['starred'] != null }`；更彻底的做法是抽一个 `parseStarred(json)` 工具函数 |
| **D-007** | `lib/features/discover/widgets/discover_album_widgets.dart` `DiscoverRecentAlbumRail` | 容器宽度不同走两条分支（scale>1.3 的 spotlight / 普通字号的 ListView） | 两条分支**共用同一个 `Key('discover-recent-spotlight')`**，key 与其它分支冲突、Widget 复用行为不可预期 | P1 | spotlight 分支换独立 key（如 `ValueKey('discover-recent-spotlight-spot')`） |

### D-006 展开（最该先修的一条）

```dart
// lib/data/models/artist.dart:31  —— 现状（错）
starred: json['starred'] != null,

// lib/data/models/song.dart:227-230 —— 正确写法（照抄这个）
starred: switch (json['starred']) {
  bool value => value,
  _ => json['starred'] != null,
},
```

影响面：艺人 / 专辑详情页的「已收藏」标记会与实际服务端状态相反，
用户点一下「取消收藏」会发现状态没变（因为 UI 本来就显示成已收藏）。
**建议修复后同步更新集成侧 / 卡片的收藏镜像口径。**
