### 测试基建踩坑记录（后续写测试直接抄，别再踩）

1. **GoRouter**：页面里会 `context.go()`，测试树里必须真的挂 GoRouter 控件。
   - `MaterialApp.router` **没有** `home` 参数；flutter 的 `Router` **不接受** `child`；
     直接 `Router(routerConfig:)` 会编译不过。
   - 唯一可行姿势：**`GoRouter` 自带 `/smoke` 路由 + `MaterialApp.router(routerConfig: router)`**，
     页面作为该路由的 `builder` 内容。否则 `No GoRouter found in context`。
2. **`pumpAndSettle` 会超时**：`AppSettingsPage` / `EditLibraryPage` 开局拉数据转圈，
   永远等不到静止。改用**有界 pump 循环**（`15 × 50ms`）代替。
3. **私有开关组件**：`_MusicFlowToggle` 是 `AnimatedContainer`（外层 52×30 底槽 +
   内层 `AnimatedAlign` 滑块），`find.byType(AnimatedContainer)` 会匹配到 3 个，
   必须按 `(w is AnimatedContainer && w is! AnimatedAlign && w.decoration is BoxDecoration)` 挑。
4. **ListView 骨架**：`MusicFlowProviderListSkeleton` 是 `ConsumerStatefulWidget`，
   外层必须套 `ProviderScope`（否则 `Bad state: No ProviderScope found`），
   且要给它有限高度（默认无界会 layout 报错）。
5. **SharedPreferences 桩**：`SharedPreferences.setMockInitialValues({...})` 后取 `getPrefs()`。
6. **L10n**：`AppLocalizations` 是 abstract，不能 `const AppLocalizations()`；
   取当前 locale 用 `lookupAppLocalizations(const Locale('zh'))`。
7. **`find.ancestor` 的 `matching` 只吃 `Type` 或 `Finder`**，传
   `find.byWidgetPredicate((w) => ...)` 会直接编译不过；要按「组件 + 字段」挑，
   用 `find.byWidgetPredicate` 单独找、或 `find.widgetWithText(MusicFlowChoiceRow, 文本)`
   （注意第一个参数是 `Type` 不是 `Finder`）。
   另外**同一行里 title 与 description 是同一个字符串时**，`find.ancestor` 会对每个
   Text 起点各返回一个祖先，必须取 `.first`。
8. **没有独立 Switch 组件**：设置行的开关是 `MusicFlowPressable(minimumSize: Size(60,48),
   onPressed: () => onChanged(!enabled))`，且 `semanticsMode = singleNode` 不产语义节点
   ——`find.bySemanticsLabel` 必然 0 命中。按 `w is MusicFlowPressable && w.minimumSize == const Size(60, 48)` 定位。
   同理「配置」按钮是 `MusicFlowIconButton(label: '配置' + 标题)`，与标题是兄弟节点，
   不能用 ancestor 找。
9. **Toast / 弹窗链路**：`showMusicFlowMessage` → `showMusicFlowToast` 走
   `Overlay.maybeOf(context, rootOverlay: true)`。用 `MaterialApp` 时它自带 root
   Overlay；但**自建 Navigator 树时必须显式挂一层 `Overlay`**，否则 toast 静默不显示
   （组件确实渲染了，只是没有 root overlay 可挂）。断言用 `find.byType(MusicFlowMessage)`。
10. **StreamProvider 覆盖要「先订阅再推事件」**：`overrideWith((ref) => ctrl.stream)`
    时，`ref.invalidate()` 会**重新订阅**（broadcast 流不补发旧事件）。
    所以交互 → `invalidate` 后要先 `pump()` 让订阅发生，再 `ctrl.add(...)`，
    推完还要 **2 帧**才落到渲染（第一帧 AsyncData，第二帧出列表）。
11. **drift 真库在测试里可用**：`AppDatabase()` 的 native 连接会问 path_provider 要
    文档目录，用
    `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger.setMockMethodCallHandler(
      const MethodChannel('path_provider'), ...)` 指到 `/tmp/...` 即可；
    不用 mock 时只是写不进去（update 影响 0 行不报错），读路径仍可用。
12. **置灰按钮静默失败**：`tap` 一个 `onPressed == null` 的按钮不会报错、只是没反应，
    排查时先自诊断 `expect(widget.onPressed, isNotNull)`，别直接断言「回调次数」。
13. **先「展开」再「推数据」**（这次踩得最深的一条）：折叠态下 `AppDrawer` **不读**
    `librariesProvider`，`librariesProvider` 也就没有订阅者；此时往
    `StreamController.broadcast` 里 `add(...)`，事件**直接被丢弃**，等再展开就永远是
    骨架屏/错误态。顺序必须是：`_expand()` → `repo.watchCtrl.add(...)`。
14. **GoRouter 每用例必须新建（不能做文件级单例）**：抽屉的「添加音乐库 / 编辑音乐库」
    走 `_closeDrawerAndPushLocation` → `GoRouter.push(...)`，而 `push` 落在
    `WidgetsBinding.addPostFrameCallback` 里。共用单例 router 时，前一个用例推的
    `/login?add=true` 会**泄漏到下一个用例**（下个用例开屏就已经在 /login，抽屉压根没渲染，
    `查看音乐库` 一个都点不到）。改成 `_routerFor()` 每次返回一个新的 `GoRouter`。
15. **抽屉必须挂在真正的 `Drawer`（独立路由）里**：`MusicFlowDrawerLibraryRow` 的
    `onSelected` 会 `Navigator.of(context).pop()`。如果 `AppDrawer` 是直接挂在根路由
    `Scaffold.body` 上，这个 `pop` 会**把根路由一起弹掉、整棵树被卸载**，之后所有断言
    全是 0 命中（看起来像「数据没推进去」，其实是树没了）。正确姿势：
    `Scaffold(drawer: Drawer(width: 320, child: AppDrawer(...)))`，用
    `_scaffoldKey.currentState!.openDrawer()` 开抽屉。
16. **走 post-frame 回调的打开动作，必须 `pumpAndSettle()` 而不是单帧 `pump()`**：
    `_closeDrawerAndPushPage` 先 `navigator.pop()` 再把页面交给 `onOpenPage`，
    这一步在 `addPostFrameCallback` 里；只 `pump()` 一帧会断言到空列表。
17. **关动效只能 `MediaQuery.of(context).copyWith(disableAnimations: true)`**：
    骨架屏 shimmer 用 `AnimationController.repeat()`，`pumpAndSettle` 永不静止。
    但直接写 `MediaQuery(data: const MediaQueryData(disableAnimations: true), ...)`
    会把 `size` 退化成 `0×0`，**整个抽屉被压扁**（导航只渲染出 6 行、点击全部落空，
    hit test 打到 `_RenderColoredBox` 上）。
18. **假仓库不要 `close()` `watchCtrl`；整个测试文件共用一个 `AppDatabase`**：
    `AuthNotifier._init` 会 `await watchLibraries().first` 并在测试收尾后写 state，
    收尾时 close 控制器会触发 `Tried to use AuthNotifier after dispose` 的假失败；
    而多用例各自 `AppDatabase()` 又会有 drift 的「created multiple times」告警
    （用文件级懒加载单例 `AppDatabase get _db => _sharedDb ??= AppDatabase();`）。
19. **`ProviderContainer implements Ref<Object>` 而非 `Ref<Object?>`**：纯容器测试里想直接
    `PeerRemoteControlNotifier(container)` 会报 `argument_type_not_assignable`，必须套一层
    只转发 `read` 的适配器（`class _ContainerRef implements Ref<Object?> { ... }`）。
20. **测试桩漏覆写基类方法 = 静默零命中**：`TestPlayerNotifier` 里 `pause()/seek()` 已有实现但
    不记调用，自己新加的 `calls/seeks` 列表永远为空 → 断言「期望 1 次实际 0 次」看着像
    「源码没跑到」，其实是桩没录。本次 7 例红全是这一个原因，先查桩再怀疑源码。

21. **mocktail 桩必须把 `route()` 当返回值用**：`route()` 的返回值就是伪造的 HTTP
    响应。写成 `route(...); return <String, dynamic>{};`（只当副作用调用）会让**所有**
    响应恒为 `{}` —— 注册拿不到 peerId、队列拿不到 currentIndex，整批用例连带变红
    （本次 22 例红全由此起）。每个桩都要 `return route(...) as Map<String, dynamic>`。
22. **`reqs` 每例新建，不要 `clear()`**：上一例 `unawaited` 的 register/heartbeat/
    local-status 会迟到打到下一例，共享 list 会把邻例请求算到本例头上。
23. **`emit()` 之后要排空 700ms，不是 30ms**：本端队列镜像是 **600ms debounce**
    （源码 `_watchLocalQueue`），等不满 700ms 回调会落到下一例去。
24. **首轮 tick 是 `unawaited`，`await switchTo()` 返回时 smooth 仍是 0**：
    断言轮询结果前必须再显式 `await ctrl.pollOnce()`，否则读到初始值 0（本次两条用例
    就是这样红的，打 print 才看出 `after switchTo smooth=0.0 / after pollOnce smooth=8.022`）。
25. **「暂停态不外推」的采样 position 必须不前进**：源码 `_tick` 有「position 在前进
    → 判在播」的**在播自愈**，给一个仍在前进的 `STOPPED` 采样会被强制改判
    `PLAYING` 再走外推（实测 12.0 + 1.003s = 13.003）。断言这类分支前先看采样有没有
    被自愈改写。

26. **桩只在 provider 被首次读取时才 new 出来**：`late final _FakeCastPeer cast;` 这类
    桩要等到控制器真正读 `castPeerControllerProvider` 才赋值。上一例把 `cast.setActive(...)`
    写在 `setUp` 之后、控制器读之前，打到的还是**上个容器那个已 dispose 的桩**
    （`Tried to use _FakeCastPeer after dispose was called`）。修法：`setUp` 里显式
    `container.read(castPeerControllerProvider)` / `container.read(dlnaCastProvider)` 把桩先逼出来。
27. **loading 那次推送的 `items` 不是空列表**：`requestSwitchList()` 先把 `_switchPeers`
    清空再 `_pushSwitchList(loading: true)`，所以这一推只剩「本机行 + 刷新行」——
    比真实列表**短一截**而不是空。别按 `items.isEmpty` 断言，按长度/首行的 `current` 判。
28. **5s tick 的去重会被首轮 nowPlaying 先占掉**：`requestSwitchList()` 末尾会并行拉一轮
    「正在播放」并重推，这一步已经把 `_lastSwitchKey` 定住了，所以**紧接着的那一拍 tick
    会被去重拦掉**。要验证「内容变了会推」，得先改一次内容（如 `nowPlayingTitle`）再推进一个 tick。


29. **真 `PlayerNotifier` 的构造期会摸 `path_provider`**：`PlayerNotifier` 构造里 `_init()`
    走移动平台分支会 `initAudioService()` → `flutter_cache_manager` 问 path_provider 要临时目录。
    测试里没装插件，`MissingPluginException` 会**穿透构造函数**（`setUpAll` 直接炸）。
    必须在 `main()` 里给通道落点：
    `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger.setMockMethodCallHandler(
    const MethodChannel('plugins.flutter.io/path_provider'), (call) async => '/tmp/xxx');`
    （别用 `MethodChannel.setMockMethodCallHandler`，v3.9 起已 deprecated，analyze 会报 `deprecated_member_use`。）
    `LocalStorage` 还另外要 `SharedPreferences.setMockInitialValues({})`，否则
    `getInstance()` 抛 `MissingPlugin`（channel `shared_preferences` / `getAll`），
    同样从 `setPlaybackMode` → `_persistPlaybackMode` 冒出来。
30. **`clamp(-1, len-1)` 的越界只有「越下界」才算 fallback**：`restoreStateForCast` 用
    `currentIndex.clamp(-1, queue.length - 1)` 取落点，只有传 **`-1`** 才落到
    「`restoredIndex < 0` → 退回调用方给的 `currentSong`」；传 `99` 会被夹回队尾（走的是
    「取队尾那首」）。要打 fallback 分支就必须传 `-1`，这也是用例写成
    「index 越**下**界」而不是「越界」的原因。
31. **`next()` 在单测里会掉进真网络深路径**：`playNext` 之后顺手 `await next()`，
    会一路进 `playSong` 发真实请求，实测把整个 test 挂住 **2m17s**，并以
    `Bad state: Cannot close sink while adding stream` 收场（后续用例集体
    `did not complete`）。投屏 / 队列同步这类「只改状态」的用例，断言只落在 state 上，
    别顺手调会自动续播的下游方法。
    另外落盘是**进程内共享**的：`persist=true` 的用例写完会留下 `playback_mode`，
    下一个「persist=false 不落盘」的用例必须 `(await SharedPreferences.getInstance())
    .remove('playback_mode')` 清场，否则读到上一条残留而误判。

### 6.4 本轮新踩的坑（续 29 起，写测试直接抄）

29. `HttpRequest` 取路径是 **`req.uri`**，写 `req.requestUri` 编译不过（没有这个 getter）。
30. `RawDatagramSocket.send` 返回的不是 `Future`，`unawaited(s.send(...))` 会报「参数必须是 `FutureOr<Future<void>>`」，直接顺序调用就行。
31. `init(streamUrlBuilder:)` 收的是 **`Future<String> Function(String)`**（换无鉴权 token 是异步的），写成同步 `String Function(String)` 会在 4 个调用点各报一次类型错。
32. `probeEnqueueSupport` 返回 `Future<bool>`，断言前必须 `await`，否则 matcher 收到的是 `Instance of 'Future<bool>'`。
33. `DlnaManager` 默认 `playMode` 是 **`all`**（模长度绕回队首），写 order 语义的断言前先 `setPlayMode('order')`，否则「末首 next」会落到 0。
34. `DeviceCapability` 默认 **`supportsDirectHttp = true`**（另两项 false），「还没探测」的状态不能按全 false 断言。
35. `copyWith` 传 null 清不掉字段（见 D-022），要造「没有 RenderingControl 的设备」只能直接 `new DlnaDevice(...)`。
36. `startCast` 建链时就推了一帧 `onTrackChanged` / `onStatusChanged`，`detachClientKeepalive()` 之后断言「零推送」会拿到 1 条历史 —— 先快照基准量再比。
37. 测墙钟续播时**真实时长取长曲（600s）、设备上报时长取短（8s）分开摆**：只按设备上报时长摆的话，`wallDone` 会在同一个观测窗里把游标多推一档（期望 1 变 2）。
38. SSDP 被动监听会把**真实局域网 renderer** 混进 `devices`，任何 `devices.isEmpty` / `hasLength(1)` 都会偶发红 —— 一律按 `location` / `id` 过滤后再断言。
39. `onDevicesChanged` 每次 `_handleSsdpEvent` 也推一次，数「推送次数」会并发漂移 —— 改成在推送内容里找「该设备的相应变化」。
40. 假 SOAP 设备是**记账在前、报错在后**（`SetVolume` 先 `setVolumeCalls.add()` 再落 fault 分支），所以「下发失败」不能用「没记账」来断言，只能断言状态没被回写。
41. `one` 模式在 `next()` 里走 `default` 分支（线性前进、不重放当前曲），不是「重播自己」。
42. 往 1900 端口发 NOTIFY 要走「物理网卡多播 + 回环单播」双路：只发多播会被 `_skipInterface` 过滤掉，只发回环又被生产端的接口过滤规则挡住，双路发最稳。
43. 本机（Windows 控制端）用 paramiko 拉远端文件前必须 `export MSYS_NO_PATHCONV=1`，否则 argv 里的 `/workspace/...` 会被 Git Bash 转成 PortableGit 路径；另外 `stdout.read()` 只能读一次，读空后 `readlines()` 返回空列表。
44. `seek()` 把状态写进**私有 `_currentStatus`、却一次都不推** `onStatusChanged`，所以「拿回调列表最后一条去断言状态」会直接 `Bad state: No element`
（列表压根是空的）—— 这条路径的失败信号是「什么都没推送」，不是「写错了值」。要钉住它只能断言外显：设备侧（Stop 已下发 / 新流没建起来）
+ `isCasting` / `castQueueIndex` 不回滚 + 回调次数不变。
45. 往 `lib/` 里插 `[D-xxx]` 注释会把该行之后的行号整体后推（本批推了 7~14 行），lcov 的 `DA:` 行号跟着变 —— 文档里写未覆盖清单必须声明「按哪版行号」，
