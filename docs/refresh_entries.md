# 双端刷新入口说明

> 本文档梳理 Echo 客户端在「安卓 / Windows」两端的刷新入口，作为后续维护与双端对齐的依据。
> 核心结论：**触屏端（安卓）用下拉刷新，桌面端（Windows/指针）用显式刷新按钮。** 二者不互相替代，各自提供最顺手的入口。

---

## 一、总览

| 能力 | 安卓（触屏） | Windows（桌面/指针） |
| --- | --- | --- |
| 下拉刷新手势 | ✅ 支持（无文字气泡） | 无（鼠标不触发下拉） |
| 区块内刷新按钮 | ✅ 有（如随机歌曲「换一批」） | ✅ 有（同一套按钮） |
| 失败后的手动重试 | ✅ 有 | ✅ 有 |
| 刷新结果的视觉反馈 | 无文字气泡，仅动画/内容变化 | 无文字气泡，仅动画/内容变化 |

两端共用一套刷新逻辑与结果处理，区别仅在「怎么触发」：

- **安卓**：既可整页下拉刷新，也可用区块内的刷新按钮；
- **Windows**：只通过区块内刷新按钮 / 失败重试按钮触发，下拉手势不生效（鼠标拖动不会产生下拉张力）。

---

## 二、下拉刷新组件（`EchoRefreshView`）

- 文件：`lib/core/design/components/echo_refresh_view.dart`
- 实现：基于 Flutter `RefreshIndicator.noSpinner` 封装，统一处理下拉「进行中 / 成功 / 失败」的状态机与轻量反馈。

### 安卓触屏端（`isAndroidTouch == true`）

- 判定：`!kIsWeb && defaultTargetPlatform == TargetPlatform.android`
- 行为：**恢复可用**的下拉刷新手势（整页下拉即可刷新），但**不再弹出文字气泡**，避免与正常向下滚动冲突时出现「下拉刷新」文字干扰。刷新时仅有下拉指示器与内容更新的视觉反馈，全程无文字提示。

### 桌面 / 其它端

- 不渲染下拉手势相关的文字气泡，也不依赖下拉触发（`RefreshIndicator` 本身需要触屏张力，鼠标拖动不会触发）。
- 刷新完全靠页面内的显式刷新按钮。

---

## 三、各页面刷新入口

### 1. 首页/发现页（`discover_page.dart`）

- **整页刷新**：安卓向下拉动整页 → `EchoRefreshView(onRefresh: _refresh)`；桌面无下拉，需用区块按钮。
- **随机歌曲「换一批」**：区块标题右侧刷新图标按钮（`_refresh`），双端均可用。
- **随机歌曲加载失败重试**：错误态内「重试」按钮（`onRetry`）。
- 打开页面默认不触发远程请求（秒出本地缓存），仅在播放 / 手动刷新 / 收到歌单变更推送时按需拉取。

### 2. 喜爱/星标页（`starred_page.dart`）

- **下拉刷新**：页面用 `EchoRefreshView` 包裹，安卓可下拉刷新（行为同上）。
- **失败重试**：错误态提供重试入口。

## 四、代码对照

| 作用 | 文件 | 位置 |
| --- | --- | --- |
| 下拉刷新组件（含安卓去文字气泡） | `lib/core/design/components/echo_refresh_view.dart` | `build()` 中 `isAndroidTouch` 分支 |
| 首页整页下拉刷新 | `lib/features/discover/pages/discover_page.dart` | `<EchoRefreshView onRefresh: _refresh>` |
| 随机歌曲「换一批」按钮 | 同上 | 区块标题 `trailing` |
| 喜爱/星标页下拉刷新 | `lib/features/library/pages/starred_page.dart` | 各处 `EchoRefreshView` |

---

## 五、对齐原则

1. **刷新行为统一**：两端共用 `_refresh` 等刷新回调与 `EchoRefreshView` 状态机，避免各写一套导致行为漂移。
2. **入口随平台适配**：触屏给下拉，指针给按钮，互不冲突。
3. **不弹文字气泡**：双端刷新均以「指示器动画 + 内容更新」反馈，避免文字提示干扰浏览。
4. **失败可重试**：任何刷新失败态都保留显式重试入口，防止「点了没反应」。
