# 首页「HA 卡片整体块」PRD（简单版）

> 状态：待评审 · 作者：许清楚（PM） · 面向：架构师做系统设计
> 参照物：HA 自定义卡片 `hass-musicflow-card/src/musicflow-remote-card.js`
> 落地仓库：`MusicFlow-client`（Flutter，Android + Windows 桌面）
> 本文只固化**产品口径与验收标准**，不含实现代码。

---

## 1. 产品目标

用户现在想在客厅音箱上放首歌，路径是「首页 → 随便点一首 → 进全屏播放页 → 打开播放端切换器 → 选设备 → 返回」，来回至少 4 跳；而他已经有一张成熟的 HA 控制面板卡片，能在一屏里完成「选设备 + 看歌词 + 控播放 + 改队列 + 调音量」。

本需求把这张卡片的整体能力**作为首页的一个分区**搬进客户端：用户在首页第一屏就能选家里的 DLNA 音箱/群组、看实时歌词、控播放、改队列、调音量，不必进播放页；同时它沿用客户端**已有的首页分区可配置框架**（可隐藏、可拖拽排序），不额外引入第二套配置体系。

---

## 2. 用户故事

| # | 用户故事 |
|---|---|
| US-1 | 作为家里有多台音箱的用户，我想在**首页第一屏**就把播放切到客厅音箱，不用先点进某首歌再进播放页找切换器。 |
| US-2 | 作为正在听歌的用户，我想在首页**直接看当前这句歌词**，不用进全屏播放页。 |
| US-3 | 作为喜欢边听边改队列的用户，我想在首页**一键展开队列**并跳/删曲目，改动立刻作用于我正在控制的那台设备。 |
| US-4 | 作为用 Windows 桌面的用户，我想这个块**在大屏上放大一些**（歌词多显示几行、封面更大），而不是手机上那个尺寸硬拉宽。 |
| US-5 | 作为只在本机听歌的用户，我觉得这个块碍事，我想去「编辑首页模块」**把它关掉或拖到最下面**，关掉后它不再偷偷请求服务端。 |
| US-6 | 作为切换了控制目标的用户，我期望**只是换了个遥控对象**：客厅音箱继续播它自己的队列，我本机原来听的歌不会被搬走。 |

## 3. 已拍板决策（固化，不改）

| # | 决策 | 固化口径 |
|---|---|---|
| D1 | 控制谁 | 选 **B**：块内**能切换控制目标**（DLNA 音箱 / 群组），客户端当**遥控器**，不只是控制本机播放。 |
| D2 | 保留能力 | 控制条、播放端切换器、实时歌词、播放队列、音量 —— **全部保留**。**明确不做媒体库浏览**。因此 HA 卡片里「队列 / 媒体库 / 音量」三面板互斥，在本需求中退化为**队列与音量两者互斥**。 |
| D3 | 高度 | **固定高度，内部滚动**，不做折叠/展开。 |
| D4 | 默认位置与可见性 | **默认置于首页最顶部且可见**；用户可在首页分区编辑页关闭它或拖到别的位置。 |
| D5 | 平台布局 | Android 与首页**同宽单列**；Windows 桌面**放大**。具体放大幅度/是否占半栏/是否歌词与队列并排 → 本文 §6 给出建议默认值。 |

### 明确不做（Out of scope）

1. **媒体库浏览**（`_renderMediaBrowser()` 整块能力不做）。
2. **拆分块内模块各自排序**：控制条/歌词/队列/音量是**一个整体分区**，在编辑页里只有一行、一个开关、一个把手，不做二级可配置。
3. **折叠 / 展开**：块高度恒定，不提供收起态。
4. **控制目标切换时迁移队列**：切换只改控制目标，不推本地队列、不投屏、不清空对端队列。
5. **群组增减成员的管理模式**（HA 卡片里点群组进管理模式加减小弟）——本需求不做，群组只作为可选项。
6. **改首页分区框架本身**：沿用现有 registry / 编辑页 / 布局合并，不新建第二套配置。
7. **改后端**：所有能力复用现有 peers / 队列 / 歌词 / 音量接口，无新增服务端契约。

## 4. 需求池

优先级：P0 = 必须有（不做则需求不成立）；P1 = 应该有（影响体验完整性）；P2 = 锦上添花（可排后续迭代）。

### P0（Must have）

| # | 需求 | 做什么 | 验收口径 |
|---|---|---|---|
| R1 | 新增分区 key 并注册 | 往既有分区体系新增一个 key（默认建议 `remote-control`，见 §6-Q1），接入 `home_section_registry.dart` 的常量清单、显示名映射、编辑顺序构建。 | 5 个旧 key 行为**完全不变**；新 key 在 registry 里可被 `kDefaultHomeSectionKeys` / `homeSectionDisplayName` / `buildHomeSectionEditOrder` 三处正确识别。 |
| R2 | 默认置顶可见 | 无用户自定义布局时（首次安装 / 清除设置），该块渲染在首页**第一个**位置。 | 清空 `home_section_layout_v1` 后冷启动，块出现在所有推荐分区之前；服务端分区清单**已下发且不含该 key** 时，块**依然置顶渲染**（见 §6-Q2，这是本需求最大风险点）。 |
| R3 | 可隐藏 | 用户可在「编辑首页模块」页用行尾开关关闭该块。 | 关闭并保存 → 首页立即不渲染该块，返回首页无需重启；再次打开 → 立即恢复渲染。 |
| R4 | 可排序 | 用户可在编辑页拖拽该块到任意位置。 | 拖到第 3 位保存 → 首页该块出现在第 3 位；拖拽交互与既有 5 个分区一致（行尾把手，不与开关手势冲突）。 |
| R5 | 编辑页文案 | 编辑页该行显示中文名（建议「播放控制」，见 §6-Q1）；中英双语齐备。 | 中文环境显示中文名、英文环境显示英文名；不做硬编码字符串，走 l10n。 |
| R6 | 控制条 | 提供 7 个控件：队列、播放模式循环、上一曲、播放/暂停、下一曲、喜欢、音量入口。图标与语义对齐 HA 卡片控件行。 | 7 个控件齐全且可点击；播放/暂停图标随当前状态切换；播放模式点击后在既定模式间循环且图标同步；「喜欢」反映当前曲收藏态并可切换。 |
| R7 | 进度条 | 显示已播时间 / 总时长 / 可拖动进度条，拖动即 seek。 | 播放中进度**平滑前进**（不跳秒）；拖动后进度条与服务端回读一致；未播放时进度条不可拖动。**注**：进度条用于 seek，但块内**不做自动播放/自动点歌**。 |
| R8 | 播放端切换器 | 横向列出可用播放端（本机 + DLNA / AirPlay / 群组），当前控制目标高亮；点击即切换控制目标。 | 列表与 `GET /peers` 一致；当前目标高亮与全局控制目标一致；**离线设备不参与选择**（对齐 HA 卡片 `p.available !== false` 过滤口径）；无任何可选项时走 R15 空态。 |
| R9 | 实时歌词区 | 块内固定高度歌词视口，随时间自动滚动，当前行高亮。对齐 HA：行高 20、当前行固定第 2 槽、视口 4 行（Android）。 | 播放中当前行高亮并自动滚动；切换歌曲后歌词随之更新；**歌词多少不影响块总高度**；无歌词时走 R15 空态。 |
| R10 | 队列面板 | 点「队列」按钮展开：表头显示曲目总数 + 清空 + 关闭；列表可跳播、可删除、可滚动。 | 展开/收起不改变块总高度；列表内滚动不带动整页滚动；点某首 ▶ 后该曲成为当前播放曲；删/清后列表与服务端一致。 |
| R11 | 音量面板 | 点「音量」按钮展开：静音键 + 音量滑条（实时显示百分比）。拖动即下发。 | 拖动时音量实时作用于**当前控制目标**（远端设备即控远端）；静音键切换生效；面板打开时块高度**零跳变**（对齐 HA 的 `volmode` 原地隐身）。 |
| R12 | 队列与音量互斥 | 任一时刻最多只有一个面板打开；打开一个自动关闭另一个；点面板外部空白关闭。 | 打开队列再点音量 → 队列关闭、音量打开；点块内空白 → 当前面板关闭；点面板内的交互元素（列表项/按钮/滑条）**不关闭**面板。 |
| R13 | 控制目标切换语义 | 切换 = **纯 UI 控制目标切换**（对齐服务端/前端 `switchPeer`）：只改控制目标，**不推本地队列、不自动投屏**；切换后 UI 镜像该设备当前播放。从本机切走时保存本机快照并暂停本机；切回本机仅恢复控制目标（对端**继续播放**、不清空对端队列）。 | ① 本机在播 A 时切到客厅音箱：本机暂停，客厅继续播它自己的歌，块内显示客厅的曲名/歌词/队列；② 再切回本机：客厅**仍在播**，本机恢复原状态；③ 全程不发生「把本机队列推给音箱」。**可直接复用 `cast_peer_provider` 的 `switchTo` / `backToLocal`，不得另起一套。** |
| R14 | 固定高度 + 内部滚动 | 块总高度恒定；歌词区、队列列表各自内部滚动；块内任何状态变化（有/无歌词、面板开合、曲目长短）都不改变块高度。 | 反复切换「有歌词↔无歌词」「开队列↔关队列」，首页**无布局跳动**（后续分区位置不动）；歌词区与队列列表可独立滚动，滚动不触发首页整体滚动。 |
| R15 | 空态 | 三类空态各给明确呈现：① 无可控制设备（peers 为空 / 未登录 / 全离线）；② 有设备但当前未在播放；③ 当前曲无歌词。 | ① 显示「暂无可控制设备」提示 + 刷新入口，**不显示空白块**；② 显示「未在播放」，控制条中除播放/切端外置灰不可用；③ 歌词区显示占位文案（建议「暂无歌词」，见 §6-Q4），高度与其他态一致。 |
| R16 | 加载态 | 首次进入首页、peers / 状态未就绪时显示骨架占位。 | 骨架高度 = 最终固定高度；数据到位后**原地替换**，不产生高度跳变；不出现先空白后撑开的抖动。 |
| R17 | 错误态 / 离线 | 连接异常时块顶部显示一条告警条，块体保持可用高度。 | 对齐 HA 的两级告警：WS 断开 REST 兜底 →「连接恢复中」；完全不可达 →「无法连接」；轮询连续失败判定离线后，控制目标行标注离线；**告警条出现/消失不改变块高度**。 |
| R18 | 数据源 | 块内所有状态读客户端自己的 provider（`cast_peer_provider` / `status_lyrics_provider` 等），**不读 HA entity、不经过 Home Assistant**。 | 代码里无 HA entity / hass 相关依赖；断网直连后端时行为与现有播放页一致。 |

│   歌名 - 艺术家                          ┌─────────┐  │  104
│   · 上一行歌词（淡）                     │         │  │
│   ● 当前行歌词（高亮，固定第 2 槽）      │  封面   │  │
│   · 下一行歌词（淡）                     │ 92×92   │  │

│   ≡    🔁    ⏮    ▶/⏸    ⏭    ♡    🔊                │  ~56

    ↑ 总高度固定（建议 280dp，见 §6-Q5），不随内容变化

 点 ≡  → ④ 队列面板：覆盖 ②+③，标题「队列 (N)」+ 清空 + ✕，列表内部滚动

### 5.3 Windows 放大态（建议方案：单列加高，**不占半栏**）

```
┌────────────────────────────────────────────────────────────────┐
│ ① [本机] [客厅音箱] [厨房] [群组 ▾]        （行高放大 ~52）     │
├───────────────────────────────────────┬────────────────────────┤
│ 歌名 - 艺术家                          │                        │
│ 歌词视口扩到 8 行                      │      封面 160×160      │
│ （当前行仍固定第 2 槽）                │                        │
├───────────────────────────────────────┴────────────────────────┤
│        ≡   🔁   ⏮   ▶   ⏭   ♡   🔊      （控件放大、居中）      │
│        01:23 ──────────●────────────────── 04:05                │
└────────────────────────────────────────────────────────────────┘
                     建议固定高度 360dp
```

**建议默认**：Windows 走**单列加高**，不做半栏、不做歌词与队列并排。
理由：现有首页是单列纵向分区流（`discover_page` 按 key 顺序纵向排列），做半栏等于改首页布局骨架，超出本需求范围；「放大」用加高 + 元素放大实现，成本低且风险可控。若产品侧坚持半栏，需另开需求。

### 5.4 与 HA 卡片的对齐点 / 差异点

| 维度 | HA 卡片 | 本需求 | 结论 |
|---|---|---|---|
| 整体分区顺序 | outputs → now（曲名/歌词/封面）→ lower（控件+进度）→ 面板 | 完全一致 | **对齐** |
| 播放端切换器 | 顶部横排，当前高亮，离线过滤（`available !== false`，群组例外） | 同 | **对齐**，复用 `player_switcher` 的 peer 显示口径 |
| 歌词视口 | 行高 20、当前行固定第 2 槽、完整态 4 行、无固定歌词时留空 | 同（Android 4 行） | **对齐** |
| 控制条 7 键 | 队列 / 播放模式 / 上一曲 / 播放暂停 / 下一曲 / 喜欢 / 音量 | 同 | **对齐** |
| 音量面板 | 覆盖下半区，控件行 `visibility:hidden` 保留占位，零跳变 | 同 | **对齐** |
| 队列面板 | 覆盖整卡，虚拟滚动行高 50，表头含总数/清空/关闭 | 覆盖块内 ②+③（不是整卡） | **差异**（见下） |

## 7. 我认为最容易出歧义的三个点（给架构师的重点提示）

1. **「默认置顶可见」在现有代码里不是免费的**（Q2）：首页 base 分区列表来自服务端清单，清单非空时 `kDefaultHomeSectionKeys` 只是兜底。新增 key 必须**由客户端显式注入**，否则 D4 直接落空。这是本需求最容易踩的坑。
2. **「切换控制目标」必须是 switchPeer 语义，不是「投屏/推队列」**（R13）：块里切到客厅音箱 = 只是把遥控器指向它，本机暂停、客厅播它自己的东西、本机队列不被搬走。实现上应直接复用 `cast_peer_provider` 的 `switchTo` / `backToLocal`，**不要另写一套切换逻辑**，否则会与 mini player、播放页产生两份互相打架的控制目标状态（Q6）。
3. **「固定高度」要贯穿到所有状态**（R14 + D3）：空态、加载骨架、错误告警条、面板开合、有无歌词，全部不能改变块高度。HA 卡片是靠 `volmode` 的 `visibility:hidden` 与 `.meta` 的 `min-height: 104px` 做到的，客户端需要等价的占位策略，否则首页滚动时会看到后面的分区上下跳。
