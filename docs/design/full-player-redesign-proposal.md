# MusicFlow Android 大屏播放页改造方案（v3 · 最终实施版）

> 目标：把全屏播放页从「封面 ↔ 歌词」两页结构，改成参考截图的「歌词 ← 封面+控件 → 歌曲信息」三页沉浸式布局；去掉底部音质信息栏；保留黑胶外圈；暖黄歌词高亮（方案 A 自适应）。

**状态**：全部决策已确认并已落地代码（2026-08-29）。本文件保留设计规格作为实现对照。

### 手势方向说明（重要）

PageView 中「手指左滑 = 翻向更后页」。为满足「左滑→信息页、右滑→歌词页」，页面顺序为：

```
[ 歌词页(0) ← 封面+控件页(1) → 歌曲信息页(2) ]   initialPage: 1
```

## 2. 三页结构

```
PageView(
  controller: _pageController,
  initialPage: 1,
  children: [
    _SongInfoPage(),           // index 0：左滑到达
    _CoverAndControlsPage(),   // index 1：默认首屏
    _PlayerLyricsPane(),       // index 2：右滑到达
  ],
)
```

| 页 | index | 到达方式 | 内容 |
|---|---|---|---|
| 歌曲信息页 | 0 | 从首屏**左滑** | 歌曲名/歌手/专辑 + 三个信息分组 |
| 封面 + 播放控件页 | 1 | **默认首屏** | 黑胶封面 + 歌曲名/歌手 + 歌词行 + 工具栏 + 进度条 + 播放控制 |
| 歌词页 | 2 | 从首屏**右滑** | 全屏歌词，当前行暖黄高亮 |

顶部栏中间：3 个等宽圆点，直径 6dp，间距 6dp，选中点用前景墨色实心，未选中点 38% 透明度。

## 3. 暖黄歌词高亮 —— 需要你二选一

### 3.1 问题（实测数据）

`MusicFlowMediaVisuals` 会把舞台底色夹进「明确暗（HSL L 0.06–0.34）」或「明确亮（L 0.58–0.92）」两个带。暖黄是亮色，在亮带上物理上无法达标：

| 底色亮度 | 示例底色 | `#FFC233` 对比度 | 结论 |
|---|---|---|---|
| L=0.06 | `#0F0F0F` | 11.88 | 优秀 |
| L=0.20 | `#333333` | 7.83 | 优秀 |
| L=0.28 | `#474747` | 5.76 | 通过 |
| 0.34 | `#575757` | 4.48 | 擦边不合格 |
| **L=0.58** | `#949494` | **1.88** | 看不见 |
| **L=0.78** | `#C7C7C7` | **1.05** | 完全糊掉 |

**结论：固定暖黄在亮底封面上不可读。** 参考截图 4 张全是暗底，所以它的黄才成立。

### 3.2 解法 A —— 自适应暖黄（改动小，推荐保守选）

以 `#FFC233` 为基色，复用现有的 `_ensureContrastAcrossToward` 二分插值机制，朝该封面的前景墨色插值直到 ≥4.5:1。

| 底色 | 实际渲染色 | 对比度 | 效果 |
|---|---|---|---|
| L=0.06 | `#FFC233` | 11.88 | 与参考截图完全一致 |
| L=0.20 | `#FFC233` | 7.83 | 与参考截图完全一致 |
| L=0.34 | `#FFC335` | 4.51 | 肉眼无差别 |
| L=0.58 | `#342D1A` | 4.51 | **深棕，不再是黄** |
| L=0.92 | `#826624` | 4.55 | **暗琥珀，偏棕** |

- ✅ 100% 封面可读，复用现有令牌机制，改动集中在歌词高亮色一处。
- ❌ 亮底封面上暖黄会退化成深棕/暗琥珀，观感与参考截图不一致。
- 影响面：约 20–30% 的浅色封面（需按你的实际曲库确认）。

### 3.3 解法 B —— 锁定舞台为暗色（观感最贴近参考）

不改歌词色，改舞台：让全屏播放页**永远走暗色舞台**（在 `stage` 模式的背景上叠加固定暗色 scrim，并把前景墨色固定为浅墨）。这样暖黄在 100% 封面都是 `#FFC233`，对比度 5.76–11.88。

- ✅ 暖黄在**每一首歌**上都是参考截图的颜色；观感与 4 张参考截图一致。
- ✅ 顺带永久消除「大屏歌名歌手白底白字」这类问题——暗底 + 浅墨不可能撞色。
- ✅ Apple Music / 网易云等主流播放器的全屏页都是暗底沉浸，符合行业惯例。
- ❌ 改动更大：需调整 `MusicFlowMediaVisuals` 的 stage 分支或在大屏页加 scrim 层并固定前景色。
- ❌ 浅色封面的大屏页不再呈现「亮色舞台」个性，统一变暗。

### 3.4 我的建议

**选 B。** 理由：你要的是参考截图那一套观感——暗底沉浸 + 暖黄歌词，这两者是绑定的，只拿走黄色而保留亮底舞台，拿不到那个效果。而且 B 顺带根治了白底白字。

如果你更看重"不动现有配色体系"，选 A 也完全能用，代价是浅色封面上歌词是深棕而非黄。

## 4. 封面 + 播放控件页（首屏）详细设计

### 4.1 布局层级（从上到下）

```
SafeArea
├─ 1. 顶部栏：收起按钮 │ 3 等宽圆点指示器 │ 更多按钮
├─ 2. 黑胶唱片封面（保留黑胶外圈 + 中心孔）
├─ 3. 歌曲名（大号，居中）
├─ 4. 歌手名（中号，居中，muted）
├─ 5. 当前歌词行（1–2 行，居中，muted）
├─ 6. 工具栏：切换播放器 │ 我喜欢 │ 客户端投屏 │ 音量控制
├─ 7. 进度条 + 左右时间
└─ 8. 播放控制行：循环 │ 上一首 │ 播放/暂停 │ 下一首 │ 队列
```

> 注意：歌词行从"歌曲名上方"移到"歌曲名-歌手下方"（你的第 6 条确认）。

### 4.2 尺寸与间距（360×800 基准）

| 元素 | 规格 |
|---|---|
| 封面直径 | 视口宽度 72%（约 260dp），上限 320dp |
| 封面顶部留白 | `spacing.xl` = 32dp |
| 封面 → 歌曲名 | `spacing.lg` = 24dp |
| 歌曲名 → 歌手 | `spacing.xxs` = 4dp |
| 歌手 → 歌词行 | `spacing.sm` = 12dp |
| 歌词行 → 工具栏 | `spacing.lg` = 24dp |
| 工具栏 → 进度条 | `spacing.sm` = 12dp |
| 进度条 → 播放控制 | `spacing.sm` = 12dp |
| 底部安全区 | `spacing.md` = 16dp |
| 左右内边距 | `spacing.md` = 16dp |

### 4.3 排版

| 文本 | 令牌 | 字号 | 颜色 |
|---|---|---|---|
| 歌曲名 | `typography.headline` | 24 | `visuals.foreground` |
| 歌手名 | `typography.title` | 15 | `visuals.mutedForeground` |
| 歌词行 | `typography.body` | 15 | `visuals.mutedForeground`（70%） |
| 时间 | `typography.metadata` | 11 | `visuals.mutedForeground` |

### 4.4 控件具体规格

**工具栏（第 6 层）** — 4 个 48dp 图标按钮，`spaceEvenly` 排列，最大宽度 380dp：

| 序 | 功能 | 图标 | 现有实现 |
|---|---|---|---|
| 1 | 切换播放器 | `AppIcons.signalTower` | 直接复用，投屏态加边框高亮 |
| 2 | 我喜欢 | `AppIcons.heart` / `heartOutline` | 直接复用 |
| 3 | 客户端投屏 | `AppIcons.dlnaLocal` | 直接复用（局域网 DLNA 直投）|
| 4 | 音量控制 | 音量图标 | 复用 `VolumeButton` |

> 「客户端投屏」我映射到现有的**局域网 DLNA 直投**按钮。如果你指的是后端投屏（链路 A），告诉我，我换成对应入口。

**进度条（第 7 层）** — 复用 `ProgressBar`，左右时间用 `typography.metadata`。

**播放控制行（第 8 层，最底部）** — 5 个按钮，与参考截图一致，循环和队列分列两侧：

| 位置 | 功能 | 图标 / 尺寸 |
|---|---|---|
| 最左 | 循环（播放模式三态）| `modeIcon`，48dp |
| 左二 | 上一首 | `AppIcons.skipPrevious`，48dp |
| 居中 | 播放/暂停 | 64dp 主按钮，`emphasized` 实心 |
| 右二 | 下一首 | `AppIcons.skipNext`，48dp |
| 最右 | 播放队列 | `AppIcons.queue`，48dp |

> 循环和队列从原工具栏**下沉**到播放控制行两侧；工具栏因此从 6 个减为 4 个。

### 4.5 封面处理

- 保留 `VinylRecordCover` 的黑胶外圈、中心孔、旋转动画（你的第 4 条确认）。
- **去掉外层任何方形卡片 / `Container` 边框 / `Card` 包裹**，让唱片直接浮在背景上。
- 封面尺寸由视口宽度驱动，不做固定正方形容器。

## 5. 歌曲信息页详细设计

### 5.1 布局

```
SafeArea
├─ 顶部栏：收起 │ 3 等宽圆点 │ 更多
├─ 标题区：歌曲名（headline）/ 歌手（title）/ 专辑·标记（body，muted）
└─ SingleChildScrollView
    ├─ 歌曲信息组
    ├─ 音频信息组
    └─ 文件信息组
```

### 5.2 字段映射（**无数据自动隐藏整行**）

**歌曲信息组**

| 标签 | 数据源 | 格式化 | 缺失时 |
|---|---|---|---|
| 时长 | `song.duration` | `durationString`（mm:ss）| 隐藏 |
| 按流派 | `song.genre` | 原样 | 隐藏 |
| 唱片号 | `song.discNumber` | 原样 | 隐藏 |

**音频信息组**

| 标签 | 数据源 | 格式化 | 缺失时 |
|---|---|---|---|
| 文件类型 | `song.suffix` 或 `contentType` | 大写，如 `FLAC` | 隐藏 |
| 码率 | `song.bitRate` 或播放态 `currentBitRateKbps` | `149 kbps` | 隐藏 |
| 采样率 | `song.samplingRate` | `44.1 kHz`（原值 /1000，保留 1 位）| 隐藏 |
| 位深 | `song.bitDepth` | `16 bit` | 隐藏 |
| 声道数 | `song.channelCount` | `2` → `立体声`；`1` → `单声道`；其他 → `N 声道` | 隐藏 |

**文件信息组**

| 标签 | 数据源 | 格式化 | 缺失时 |
|---|---|---|---|
| 文件大小 | `song.size` | `34.55 MB`（/1024/1024，保留 2 位）| 隐藏 |
| 歌曲路径 | `song.path` | 尾部截断，最多 2 行 | 隐藏 |

### 5.3 分组样式

- 分组标题：20×20 图标 + `typography.title` 文字，组间距 `spacing.lg`(24dp)。
- 行高 48dp，标签左对齐 `typography.body` + `mutedForeground`，值右对齐 `typography.body` + `foreground`，过长尾部截断。
- 分组内若所有行都被隐藏，则**整组也隐藏**（避免出现空标题）。
- 采样率/位深/声道数/码率四者全缺时，音频信息组整体不渲染。
